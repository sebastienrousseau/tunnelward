## Highlights ⭐️

* **Each MCP call is decided by a tool policy**: rules permit or forbid calls by agent, provider, path, method, tool and evidence level, and a tool marked high impact needs cryptographic evidence. A denied call gets a JSON-RPC error from the gateway and never reaches the service; `tunnelward policy test` checks a policy before it ships, and a changed policy file applies without a restart.
* **A stolen token is not enough**: tokens bound to a DPoP key or a client certificate work only for their holder, paths can demand them and single use, and a high-impact call needs an `Idempotency-Key`, so a retried or replayed call returns the first answer instead of running twice.
* **Several gateways act as one**: replay caches, idempotency keys and rate limits can live in a Redis-compatible store (`[state]`), so a replay is caught whichever gateway it reaches; checks that stop replays refuse when the store is down, and rate limits fall back to each gateway's share.
* **Provider snapshots are signed for a post-quantum world**: `tunnelward providers keygen` makes a composite ML-DSA-65 + Ed25519 key, both halves of a signature must verify, and ML-DSA-65 is checked against NIST's test vectors.
