## Highlights ⭐️

* **A stdio MCP server can sit behind the tunnel**: `[target] stdio` in a connector's file starts the server per session and serves it as Streamable HTTP, with an event stream that resumes after `Last-Event-ID`. CI runs the MCP project's reference server, server-everything 2.0.1, through it on every push.
* **Claims that the evidence does not back are flagged**: a `User-Agent` or MCP `clientInfo` naming Claude or ChatGPT is compared with the provider the gateway actually saw, and a policy rule with `mismatch = true` can refuse those calls.
* **First benchmark numbers, measured exactly**: the gateway adds 125 to 160 µs at p50 to a 1 KiB MCP call (budget 500 µs) and holds 58.9 KiB of heap per idle connector connection (budget 64 KiB) and 25.8 KiB per request in flight. The p99 latency and scaling across cores are not measured yet, because the laptop used is too noisy for them; `docs/BENCHMARKS.md` has the method and each verdict.
* **The frame parser is proved, not only fuzzed**: Kani shows framing never panics, never reads past its buffer and checks a length before allocating, in CI on every push. A connector that was still registering no longer gets a request refused with TW-S001.
