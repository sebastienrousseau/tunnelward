## Highlights ⭐️

* **A rewritten tool never reaches the agent**: the connector registers with its MCP server's name, version and tool digest, then reads every `tools/list` answer on its way back. A new or changed tool (a rug pull) is refused with a JSON-RPC error before an agent can act on it, in normal and gateway-blind mode, and a route's attestation now checks the server's version.
* **Try a policy before enforcing it**: shadow paths forward what the policy would deny and write why into the audit log, so a stricter rule can run on live traffic first. High-impact tools keep their idempotency key and approval.
* **Rolling updates without dropped calls**: on SIGTERM the gateway drains its connections and the connector lets its requests finish, and both exit 0.
* **Checked against MCP itself**: passmcp finds no failing check on the MCP servers shipped here, through the whole tunnel, and the MCP conformance suite gives the same result through the gateway as without it. The first runs caught two defects, now fixed: unknown origins were served (DNS rebinding), and the stdio bridge sent a body with 202.
