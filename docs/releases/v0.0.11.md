## Highlights ⭐️

* **Agents must hold a token**: with `[agents]` the gateway is an OAuth 2.1 resource server per the MCP authorisation spec. It checks each bearer JWT's issuer, signature, audience, expiry and scopes, publishes its protected-resource metadata (RFC 9728), and never passes the token to a connector (`TW-I008`, `TW-I009`).
* **Connectors get and keep their identity without a restart**: SVIDs come from the SPIFFE Workload API or from files and rotate in place. A connector with no SVID can enrol: a one-time token bound to a SPIFFE ID buys a short-lived SVID from the gateway's CA, renewed with a new key before it expires, and `tunnelward enrol revoke` stops it (`TW-I011`).
* **Requests say which AI provider sent them**: requests from Anthropic's and OpenAI's published egress ranges are tagged from a signed, versioned snapshot (`tunnelward providers`), and a verified Web Bot Auth signature (RFC 9421) from a listed agent raises the tag from network to signature level, with a nonce replay check (`TW-I010`).
* **The README and demo stay current**: the gate now fails on a stale version in the README or a release with no capability row, and the release preflight checks that every badge renders and that the demo was re-rendered after the version bump.
