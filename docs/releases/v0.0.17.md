## Highlights ⭐️

* **Check any gateway against the protocol**: `tunnelward conformance` connects as a connector and runs six checks, from refusing a connection without `tw/1` to answering a valid registration with HTTP/2. It prints each result, as text or JSON, and fails unless all pass. The checks live in `tunnelward-conformance` (MIT OR Apache-2.0) for other implementations to run.
* **A Helm chart for the gateway**: `deploy/helm/tunnelward` runs the distroless image non-root with a read-only root, reads TLS and the admin token from Secrets, and is published as a signed OCI chart. CI runs a gateway from the chart's own config file and passes the conformance kit against it.
* **Integration tests in Java**: the Testcontainers module starts a gateway and a connector with a throwaway PKI, so a test can send agent requests through Tunnelward to a service in a container.
* **QUIC moved later**: its 17 new dependencies need a supply-chain decision first.
