## Highlights ⭐️

* **One place to change a fleet's tool policy**: `tunnelward control` signs each policy an operator publishes, and gateways with `[control]` pull it over mutual TLS. A gateway applies a bundle only if it verifies under the control's key, is newer than the one running and its policy checks, and denies every call until its first bundle.
* **Operators sign in with their company's identity provider**: the API takes OIDC access tokens, and a role from a token claim decides what each may do: view, publish, or roll back.
* **Every change has a name on it**: each publish and rollback is in the control's audit log with the operator who made it.
* **No new dependencies**: tokens are checked by the gateway's own verifier and bundles are signed with the composite key the audit log uses.
